# Pedagogical settings editor

- Keep teaching-options drafts in pure `src/lib/catalog-editor.ts` operations; IDs are generated once and never edited or derived from labels, so renames preserve identity.
- Persist through `src/lib/catalog-settings.ts` using the session client, freshly verified teacher identity and an owner-scoped update of only `settings.catalog_options`; return persisted values to the existing teacher-scoped catalog cache to preserve unrelated settings and account isolation.
- Missing settings rows and failed/invalid reads or writes fail visibly rather than creating partial rows or substituting local defaults; this editor does not provision teacher settings or alter historical records.
- Removal/restoration use `changeCatalogOptionLifecycle` with immediate single-column compare-and-set persistence and the existing cache; pure removal requires a successful teacher-scoped paginated `catalog-usage.ts` history check, while used entries keep metadata with active=false. Main lists contain active entries only; recovery updates the existing ID rather than appending one.- Unsaved teaching-option drafts are reported upward via `onDirtyChange` (draft vs persisted baseline); the Settings route guards tab switches and router/browser navigation with `useBlocker` + `UnsavedChangesDialog`, so discarding means unmounting the draft.

- Lead details/editing live in `LeadDetailSheet` + shared `LeadProfileFields`; `src/lib/lead-profile.ts` builds changed-columns-only patches (blanks → NULL, no defaults) saved owner-scoped and read back, so automations, conversion and stages stay untouched.
- Lead tasks tab (`LeadTasksPanel` + `src/lib/lead-tasks.ts`) reads/writes the canonical `public.tasks` rows by teacher_id + lead_id with read-back; it never edits automation-created tasks beyond completion, so Today/attention reuse the same rows.
