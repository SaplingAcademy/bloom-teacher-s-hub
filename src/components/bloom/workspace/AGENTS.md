# Personal notes
- Use only workspace_notes with the existing session client and RLS; freshly validate Auth identity and owner-filter writes so drafts never supply user_id.
- Board (≥768px) positions come only from workspace_notes.pos_x/pos_y (both NULL = automatic slot ordered by created_at/id, never written); drags are local Pointer Events state and save one snapped, board-clamped position on release, rolled back on failure. Below 768px keep the stacked grid without drag.
- `pinned` means "position locked" (not draggable); "front/back" moves one row past all notes through order_index (stacking order). Never mass-update positions or pinned; automatic slots never depend on pinned/order_index, so lock and layer changes never move notes, including after reload.
- Serialize optimistic mutations per owner-scoped Query cache, cancel stale reads and roll back failures; retain the create editor UUID across retries to avoid duplicate notes.
- Note moves (position) are the exception: applied to the cache synchronously and saved on their own `[...key, "position"]` mutation key, so they never set `pending`; only the latest move of a note may roll back (to its previous position) or replace it with the saved row, and the board is never refetched for a move.
- Note images go only through `src/lib/workspace-note-images.ts`: private `workspace-media` bucket at `owner/notes/note/image.webp` built from Auth + UUIDs, metadata in workspace_note_images, signed URLs only; browser re-encodes to WebP (max 1600px, no EXIF), max 3 per note.
- Image edits stay local until Save (text first, then removals and uploads); upload→row with object cleanup, file→row on removal, folder cleanup before note deletion; partial failures keep the editor open and never toast success.
- Render note content as React text only, never HTML, and reuse semantic note tokens and PT/EN dictionaries so stored colors and content remain unchanged.
- Boards are scoped by workspace_notes.project_id: NULL = personal (reads author + `.is("project_id", null)`), a project id = that project's board (all authors, by project); cache keys include the scope, project_id comes only from the route on create and is never updated (DB trigger also blocks project_id/user_id changes). Archived project boards are read-only in the UI; RLS enforces it.
- Note connections (personal board only) live in `workspace_note_connections` by note IDs, through `workspace-note-connections.ts`/`useNoteConnections`; arrows are drawn in NotesCanvas from the same live note positions (behind notes, pointer-events none); one arrow per pair, FK cascade on note delete; hidden when the migration is missing, on project boards and below 768px.
# Personal projects
- Project detail has exactly two pages (`ProjectPages`): planning (unchanged) and the project's board, mounted only when shown. Deleting a project first removes its board's Storage files (`deleteProjectNoteFiles`) and aborts on failure; rows go by FK cascade.
- Projects use only workspace_projects/phases/items through `workspace-projects-data.ts`; every read/write re-verifies Auth and filters by project/id, letting RLS grant the owner or accepted participants (`workspace_project_members`); archive/reactivate/delete stay owner-filtered, updates never send user_id/project_id and the DB sets phase/item user_id to the project owner.
# Shared projects (Etapa 2)
- Access = owner or accepted member via `workspace_project_accessible/_writable` (members write only active projects); UI derives `isOwner` from `project.user_id` to hide archive/delete and lock participants on archived projects, while RLS/triggers stay authoritative.
- Shared boards: every participant edits/moves any note; images only by the note author; deleting another author's note is owner-only and cleans files in the author's folder (`deleteAllNoteImages(owner, note, author)`).
- Progress is always derived in pure `workspace-projects.ts` from task/checklist items (0% when empty) and never stored; phase deletion relies on the FK SET NULL and the optimistic cache mirrors it.
- Detail mutations are serialized per owner/project cache with optimistic apply and snapshot rollback; link URLs are http(s)-only in meta.url and re-validated before rendering.
# Task assignees
- Assignees live only in `workspace_item_assignees` (tasks only; owner or accepted members, validated in the DB); write through `create_project_task` (task + assignees atomically) and `set_project_item_assignees`, never direct table writes. `items.user_id` is the project owner, `items.created_by` the creator (set by the DB).
- New items offer only task/link (`CREATABLE_ITEM_TYPES`); legacy checklist/note stay viewable/editable with their own type. The assignee field hides when `useItemAssignees().available` is false (migration not applied).
# Personal notebooks
- Notebook-only `NotebookFormatting` overrides shared `toggleList`, preserving unselected items and nested content while keeping toolbar/native shortcuts consistent; mouse presses on toolbar controls preserve the editor selection.
- Notebooks/pages use only the session client through `workspace-notebooks-data.ts`, revalidate Auth, filter owner/notebook/id and never update ownership/parent IDs; FK/RLS remains authoritative.
- Lazy Tiptap edits whitelisted structured JSON; derive previews from text, allow HTTP(S) links only and reject unknown documents without rewriting them.
- `NotebookAutosave` keeps page-scoped local drafts and serialized debounced writes; only latest confirmed versions update cache, failed saves retain content and block leaving until saved.
- Move a single page to its pin-group start/end; create/duplicate retries retain UUIDs and list counts/latest activity derive from existing page rows.
